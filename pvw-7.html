WHY

为什么做它

昆明富民供电局建设管理部的日常，是几十张 Excel、散落各处的台账，和「人一走、经验就走」的岗位交接。PVW 的核心承诺只有一句：让每位员工「少填 50 张表，多问一句话」。

真实痛点PVW 的解法
项目前期 / 管理 / 后期全流程靠人工填表，台账散落在 Excel 和个人电脑里电力工程全生命周期一个平台管完：可研/评审/合同/预算/招投标 → 进度/计划/工资/安全/质量/风险 → 结算/决算/工程量
老员工离职，岗位经验跟着走，新人从头摸索岗位不变人变 — 5 个同事 Agent 沉淀岗位知识，同事离职 Agent 不重训，新员工直接接岗
问一个数据要翻系统、问多人、等半天微信式对话直接问 zyrleader：调度总管自动拆任务、派给对应岗位的同事 Agent，3 秒级给出带「参考资料」的回答
电力行业合规要求严，业务数据绝不能上公网全栈私有化：MiniMax-M3 私有部署 + 本地 PostgreSQL / Milvus / Redis，数据不出域

FLOW

一句话的完整旅程

以建设管理员早上的一句「今天有哪些项目要跟进」为例 — 这是真实产品里 zyrleader 5 字诀「拆→派→检→核→收」的一次完整执行。

01 · 说
自然语言提问
在微信式对话框输入「列出所有项目并让项目经理分析风险」，支持单聊 / 群聊 / 长按加提醒。
02 · 拆
zyrleader 拆解任务
调度总管把一句话拆成结构化子任务：show_projects 查项目台账、show_risks 查安全隐患。
03 · 派
delegate_to_persona 派单
子任务通过 delegate_to_persona 工具派给对应岗位：进度风险 → 小王（项目经理），安全隐患 → 老李（安全员）。
04 · 检 · 核
同事执行 + 交叉核验
各 Agent 查询本地 PostgreSQL 业务库 + Milvus 向量知识库，流式输出答复；zyrleader 对结果做一致性核验。
05 · 收
合并汇总 + 参考资料
zyrleader 输出合并后的状态报告，底部附「📄 参考资料：项目台账 / 安全隐患清单」，来源可追溯。F5 刷新，记录全保留。
